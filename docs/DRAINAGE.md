## 2. ทางไหลของน้ำระดับพื้นที่ (`app/engines/flow.py`)
1. อ่านหน้าต่าง DEM ±2.5 กม. รอบจุด แล้วลด noise ด้วย 3×3 median
2. ทำ priority-flood (Barnes 2014) โดยใช้ขอบหน้าต่าง, cell ที่ไม่มีข้อมูล และ **cell ที่มีทางน้ำ OSM** เป็นทางออกของน้ำ
3. ในแต่ละ cell เลือกทางไหลแบบ D8 ไปยังเพื่อนบ้านที่ชันที่สุดบนผิวที่เติมแอ่งแล้ว
   ถ้าเป็นพื้นราบหรือแอ่งที่ถูกเติม จะไหลตามลำดับการเติม (ไปทางจุดที่น้ำล้นออก)
4. ไล่ตามทางไหลจากจุดนั้นจนถึงทางน้ำ ขอบหน้าต่าง หรือบริเวณที่ไม่มีข้อมูล
5. นับจำนวน cell ที่ไหลผ่านแต่ละ cell (flow accumulation) ภายในหน้าต่าง และหาแอ่งแรกบนทางไหลที่ลึก ≥0.5 ม. เป็น `accumulation_zone`

**ความมั่นใจของทิศทาง:**
`confidence = drop / (drop + 2 × noise) × (1 − filled_share)`
- `drop` คือระดับที่ลดลงจริงใน 500 ม. แรกของทางไหล
- `noise` คือความคลาดเคลื่อนของ DEM (Copernicus 1.5 ม.)
- `filled_share` คือสัดส่วนของทางไหลที่เกิดจากการเติมแอ่ง

ถ้าความมั่นใจต่ำกว่า 0.3 ระบบจะไม่ระบุทิศทาง และตอบว่า **"ไม่สามารถระบุทิศทางการระบายน้ำจาก DEM ได้อย่างน่าเชื่อถือ"**

| ตำแหน่ง | ผล |
|---|---|
| ดอยสุเทพ | ไหลไปทาง E ความมั่นใจ 0.70 ไปถึงห้วยผาลาด |
| ภูเก็ต (เนินเขา) | ไหลไปทาง E ความมั่นใจ 0.70 |
| บางกะปิ | ความมั่นใจ 0.15 → ไม่ระบุทิศทาง |
| อยุธยา | ความมั่นใจ 0.00 → ไม่ระบุทิศทาง |
| น่าน | ความมั่นใจ 0.03 → ไม่ระบุทิศทาง |

ผลทั้งหมดนี้เป็น terrain-derived flow **ไม่ใช่ข้อมูลระบบท่อ การสูบน้ำ หรือประตูระบายน้ำ**
ระดับลุ่มน้ำใช้ HydroSHEDS 15″ บอกพื้นที่รับน้ำต้นทาง (ตร.กม.) และบอกว่าจุดอยู่บน drainage corridor หรือไม่ (≥10 ตร.กม.)

## 3. การระบุพื้นที่รับน้ำ (Catchment Assignment)
ใช้การเช็กว่าจุดอยู่ใน polygon ไหนของ HydroBASINS ระดับ 5 / 7 / 12 ได้ `basin`, `sub_basin`, `catchment_id = hybas12:<id>`
- `thai_basin` คือชื่อลุ่มน้ำไทยที่พบมากที่สุดในป้ายของสถานี ThaiWater ที่อยู่ในหน่วยเดียวกัน พร้อมสัดส่วน
  - ตัวอย่าง: บางกะปิ = ลุ่มน้ำบางปะกง 55% ซึ่งแปลว่าเป็นพื้นที่รอยต่อ
- `confidence` = 0.3 ถ้าเป็นพื้นที่ราบที่ DEM บอกทิศทางไม่ได้ และ 0.6 สำหรับพื้นที่อื่น

## 4. การเลือกทางน้ำที่เกี่ยวข้อง (`selection_method`)
ระบบเลือกตามลำดับ ถ้าขั้นแรกใช้ไม่ได้จะลงไปขั้นถัดไป:
1. `drainage_based`: ทางไหลที่มีความมั่นใจพอไปถึงทางน้ำ OSM
2. `catchment_based`: ทางน้ำสายหลัก (HydroRIVERS) ของหน่วยระดับ 12 ที่จุดอยู่ ต้องอยู่ห่างไม่เกิน 2 กม. และตั้งชื่อตามเส้น OSM ที่วิ่งขนานกัน
3. `distance_based`: แม่น้ำหรือคลองที่มีชื่อซึ่งใกล้ที่สุด ใช้เป็นทางสำรองและบอกเหตุผลชัดเจน
4. `unknown`

ผลลัพธ์ส่ง `candidates` ของทุกวิธีกลับมาด้วย เพื่อให้เห็นว่าทำไมขั้นก่อนหน้าใช้ไม่ได้

## 5. การเลือกสถานีวัดน้ำที่เกี่ยวข้อง
ระบบเลือกตามลำดับขั้น แต่ละขั้นเรียงสถานีที่มีค่าล่าสุดก่อน แล้วค่อยเรียงตามระยะทาง:

| ขั้น | selection_method | เงื่อนไข |
|---|---|---|
| 1 | `same_waterway_and_catchment` | ชื่อลำน้ำของสถานีตรงกับทางน้ำที่เลือก และหน่วยระดับ 12 ของจุดอยู่ในพื้นที่รับน้ำของสถานี |
| 2 | `same_waterway` | ชื่อลำน้ำตรงกัน |
| 3 | `same_catchment` | พื้นที่ของจุดไหลลงสู่สถานี |
| 4 | `nearby` | ใกล้ที่สุดในรัศมี 15 กม. ("เลือกจากสถานีใกล้เคียง เนื่องจากยังไม่มีข้อมูล...") |
| 5 | `none` | ไม่มีสถานีที่เหมาะสม |

**การหาพื้นที่รับน้ำของสถานี:**
- `reach_network`: รวมหน่วยระดับ 12 ของทุกช่วงแม่น้ำที่อยู่ต้นน้ำของช่วงที่สถานีผูกอยู่
- `local_unit_only`: ใช้เมื่อสถานีอยู่บนคลองเล็กที่ไม่อยู่ใน HydroRIVERS จะใช้เฉพาะหน่วยที่สถานีตั้งอยู่

## 6. สถานีต้นน้ำ/ปลายน้ำ (`station_hydro_link`, `station_relation`)
**การผูกสถานีกับลำน้ำ**

| วิธี | จำนวนสถานี | ความมั่นใจ |
|---|---|---|
| `name_and_distance`: หาเส้น OSM ที่ชื่อตรงกับชื่อลำน้ำของสถานีภายใน 500 ม. แล้วเลือกช่วงแม่น้ำ HydroRIVERS ที่วิ่งขนานกับเส้นนั้นมากที่สุด (Hausdorff) | 318 | 0.5–0.7 |
| `distance_only`: เลือกช่วงแม่น้ำที่ใกล้ที่สุด | 441 | 0.25–0.4 |
| `none`: ลำน้ำเล็กเกินกว่าจะอยู่ใน HydroRIVERS | 44 | - |

**ความสัมพันธ์ต้นน้ำ/ปลายน้ำ:** ไล่ตาม `NEXT_DOWN` แล้วคำนวณระยะทางตามลำน้ำจากตำแหน่งบนช่วงแม่น้ำ ได้ 7,069 คู่
- คู่ที่ชื่อลำน้ำต่างกันได้ความมั่นใจครึ่งเดียว เพราะ HydroRIVERS เป็นโครงสร้างแบบต้นไม้ จึงแทนแม่น้ำที่แยกสายไม่ได้ (เช่น ท่าจีน, น้อย, คลองในที่ราบลุ่ม)
- `lag_hours` = null และ `lag_basis` = `not_estimated` จนกว่าจะมีข้อมูลย้อนหลังพอให้ประเมินเวลาที่น้ำเดินทาง

## 7. ฝนในพื้นที่รับน้ำ (`app/services/catchment_rain.py`)
**ฝนที่ตรวจวัดได้** จากสถานีวัดฝน ThaiWater ในหน่วยของพื้นที่รับน้ำ ช่วง 1/3/6/24 ชม.:
- ค่าเฉลี่ย, ค่าสูงสุด, ค่าเฉลี่ยถ่วงน้ำหนักตามพื้นที่ของหน่วยระดับ 12 และ `coverage` (สัดส่วนพื้นที่ที่มีสถานีวัดฝน)
- หน่วยที่ไม่มีสถานีวัดฝนจะไม่ถูกเติมค่า

**ฝนคาดการณ์** ใช้ consensus ของจุดพยากรณ์ที่อยู่ในพื้นที่รับน้ำ (`points_in_catchment`)
- ถ้าไม่มี จะใช้จุดที่ใกล้ทางออกของพื้นที่รับน้ำที่สุดภายใน 30 กม. (`proxy_nearest_point`) และระบุไว้ในผล
- ถ้ายังไม่มี จะตอบว่าไม่มีข้อมูล

## 8. Feature Set และตาราง `water_forecast_training`
job `features.snapshot` ทำงานทุกชั่วโมงที่นาที 25 โดยบันทึก 1 แถวต่อสถานี ต่อ horizon (1/3/6/12/24 ชม.)

| กลุ่ม | ค่าที่เก็บ |
|---|---|
| `features` | current, 1h/3h ago, rate_of_rise, distance_to_bank, reservoir_release=null (RID ไม่มีพิกัดเขื่อน), tide=null (ไม่มีแหล่งข้อมูล), hydro_link |
| `rain_features` | catchment_rain 1/3/6/24h, forecast_catchment_rain 1/3/6h, วิธีที่ใช้ |
| `upstream_features` | ระดับน้ำ อัตราการขึ้น และระยะถึงตลิ่งของสถานีต้นน้ำสูงสุด 3 แห่ง |
| `terrain_features` | relative elevation 500 ม. และ local depression จาก Copernicus |
| `source_versions` | method/feature version ของทุกส่วน |

- `label_due` เติม `actual_water_level_m` และ `actual_change_m` เมื่อมีค่าตรวจวัดภายใน ±30 นาทีจากเวลาเป้าหมาย
- **ป้องกันการใช้ข้อมูลอนาคต:** ใช้เฉพาะค่าที่ `observed_at ≤ as_of`, gauge window ที่มีขอบบน และ forecast run ที่ `fetched_at ≤ as_of` การย้อนเก็บข้อมูลอดีตจึงไม่ใช้ข้อมูลที่ยังไม่เกิด ณ เวลานั้น
- ย้อนเก็บ 6 ชม. ได้ 10,470 แถว
- **ยังไม่มีการ train model** ขั้นต่อไปคือ Water Forecast Engine

## 9. ข้อจำกัดสำหรับกรุงเทพฯ และพื้นที่ราบ
- พื้นที่ราบมาก (สูง 0–3 ม.) แต่ DSM มี noise ~1.5 ม. หรือมากกว่า ระบบจึงมักไม่ระบุทิศทางไหล ซึ่งเป็นพฤติกรรมที่ตั้งใจไว้
- กรุงเทพฯ เป็นระบบ polder น้ำถูกควบคุมด้วยคันกั้นน้ำ ประตูระบายน้ำ และเครื่องสูบ ทางไหลจาก DEM อาจไม่ใช่ทางที่น้ำไหลจริง
- คลองใน OSM ไม่มีข้อมูลทิศการไหล และหลายคลองไหลได้สองทางตามน้ำขึ้นน้ำลง ความสัมพันธ์ต้นน้ำ/ปลายน้ำจึงมีเฉพาะลำน้ำใน HydroRIVERS
- ขอบเขตลุ่มน้ำ 15″ ในที่ราบลุ่มอาจไม่ตรงกับเขตระบายน้ำจริง (บางกะปิได้ป้ายลุ่มน้ำบางปะกง 55% / เจ้าพระยา)
- ยังไม่มีข้อมูลพื้นที่ระบายน้ำและสถานีวัดน้ำในคลองของ กทม. (BMA)
- RID ไม่มีพิกัดเขื่อน จึงยังระบุไม่ได้ว่าการระบายน้ำจากเขื่อนไหนส่งผลต่อสถานีใด

## 10. API และคำสั่ง
- `GET /api/drainage?lat=&lon=` ให้ `local_flow`, `basin_scale` และ `catchment`
- `GET /api/location/analyze` เพิ่ม `drainage`, `relevant_waterway`, `relevant_station`, `rain.catchment` และ `reliability[]`
- `GET /api/water/stations/{code}` เพิ่ม `network` ซึ่งมี catchment, river_link, relations และ catchment_rain

```bash
python -m app.cli hydro-import          # ดาวน์โหลดและนำเข้า HydroSHEDS (~530 MB, ครั้งเดียว)

```
